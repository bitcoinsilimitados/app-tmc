## 1. What is this project?

**The Monopoly Club (TMC)** is a decentralized crowdfunding / matrix marketing DApp built on **Polygon Mainnet**.

- Users register with a referrer and buy progressive levels (1 to 15).
- Each level costs **double** the previous one (20, 40, 80, ... USDT).
- When a user fills their 3x matrix at a level, they receive a dividend and the matrix **reinvests** automatically.
- The system is implemented as a **single Solidity smart contract** (`THE_MONOPOLY_CLUB`) that holds **no user funds** — all transfers happen directly between wallets via ERC20 `transferFrom`.
- Supported tokens: **USDT**, **USDC**, **DAI**.

**Repo name:** `BASE-USDT-Forsage`  
**Package name:** `usdt-forsage`  
**Live site:** `https://themonopolyclub.com/`  
**Brand:** The Monopoly Club (`TMC`)

## 4. Smart Contract Overview (`contracts/USDT-Forsage-v2-poligon.sol`)

**Contract name:** `THE_MONOPOLY_CLUB`  
**Deployed address:** `0xC76BeEf9Af888208820d7E7e84C3ec4B73a7e3A9`  
**Network:** Polygon Mainnet (Chain ID: 137)

### Core Concepts

1. **Matrix (X3):** 3 referrer slots per level.
2. **Levels:** 1 to 15. Level price doubles each level (starting at 20).
3. **Registration:** New user pays `levelPrice[1]` (20 tokens) and is placed in the referrer's matrix.
4. **Upgrade:** User buys the next level; a new free referrer slot is found recursively up the chain.
5. **Reinvestment:** When a matrix is filled (3 referrals), it closes, the referrer gets a dividend, and a new matrix opens at the same level.
6. **Missed payments:** If a referrer doesn't have an active level, the payment is stored in `missPayments` and eventually sent as extra dividends.
7. **Profits:** Accumulated in `profits` mapping. The frontend reads this as `ganado`.

### Key Contract Functions Called by Frontend

| Function | Purpose |
|----------|---------|
| `registrationExt(address, uint256)` | Register new user with referrer |
| `buyNewLevel(uint256)` | Buy a specific level |
| `usersActiveX3Levels(address, uint256)` | Check if user has a level activated |
| `usersX3Matrix(address, uint256)` | Get referrer + referrals + blocked + reinvestCount |
| `levelPrice(uint256)` | Get price for a level |
| `missPayments(address)` | Get lost/blocked payments |
| `profits(address)` | Get accumulated profits |
| `isUserExists(address)` | Check if address is registered |
| `lastUserId()` | Total registered users |
| `owner()` | Contract owner address |

### Admin Functions (Owner Only)
- `ChangeTokenUSDT(address)` — Change primary ERC20 token.
- `ChangeTokenOTRO(address)` — Change secondary token.
- `ChangeLevelPrice(uint256, uint256)` — Override a specific level price.
- `withdrawLostTRXFromBalance()` — Withdraw stuck native tokens.
- `withdrawLostUSDTFromBalance()` — Withdraw stuck USDT.
- `withdrawLostOTROFromBalance()` — Withdraw stuck secondary token.

## 5. Frontend Architecture

### Pages (URL routing via query params)

| URL | Component | Description |
|-----|-----------|-------------|
| `/` or `/` | `Home` | Landing page, stats |
| `/?backoffice` or `/?app` | `BackOffice` | Dashboard (requires MetaMask) |
| `/?view` or `/?wallet` | `BackOffice(isView=true)` | Read-only wallet view |
| `/?privacy` | `PrivacyPolicy` | Privacy policy |
| `/?terms` | `TermsAndConditions` | Terms and conditions |
| `/?cookies` | `SiteData` | Cookie policy |
| `/?disclaimer` | `LegalDisclaimer` | Legal disclaimer |

### BackOffice State Flow

1. **Connect Wallet** — Requests `eth_requestAccounts`, switches Web3 provider to MetaMask.
2. **Set Contract** — Instantiates main contract (`TMC-v2`) and token contract (`TokenPRC20`) using the wallet address as `from`.
3. **Estado Loop** — Runs every 30 seconds to refresh:
   - User level (counts consecutive active levels starting from 1).
   - Next level price.
   - USDT balance + allowance.
   - Profits (`ganado`) and missed payments (`balanceLost`).
   - Team size + matrix details for each level.
   - Referral link generation.

### Important Frontend Files

- `src/Utils/index.js` — **Single config file** for contract address, RPC, and chain ID.
- `src/assets/abi/TMC-v2.js` — ABI for the main contract.
- `src/assets/abi/TokenPRC20.js` — Standard ERC20 ABI.

## 8. How to Contribute / How to Help

### For Humans
1. Read this file first.
2. Read `README.md` for general project info.
3. Check the Issues tab for tasks.
4. Follow the code style in the repo (2-space indentation, JSX, no comments unless necessary).

### For AI Agents
1. **Always read this file first** before proposing changes.
2. **Do not guess** contract addresses, RPC URLs, or ABI structures. Read `src/Utils/index.js` and `src/assets/abi/`.
3. **Do not introduce new libraries** without checking `package.json` first.
4. **Do not move logic** between layers without understanding the data flow (e.g. contract calls must stay in the page components, not in `App.jsx` routing).
5. **Keep routing URL-based** — the app uses query params, not React Router. Do not add `react-router-dom`.
6. **Solidity version is `>=0.5.17`** — newer syntax (e.g. `error`, custom errors) is not available.
7. **Token decimals:** Always fetch `decimals()` from the token contract. Do not hardcode `6`.
8. **The contract does not hold funds** — do not add `deposit()` or `withdraw()` functions that imply the contract stores user money.
9. **When modifying the contract:** update `src/assets/abi/TMC-v2.js` as well.
10. **Do not modify `Tutorial.md`** — it is legacy documentation for a TRON tutorial and is unrelated.
